# 节点产出

每个里程碑（M1、M2…）一个文件夹，存放**结论性文档**：测试报告、架构分层检查、实测数据汇总。这里不放可执行代码——测试在 [`tests/`](../../tests/)，工具在 [`tools/`](../../tools/)。

| 节点 | 产出 | 状态 |
| --- | --- | --- |
| [M1](m1/) | [测试报告](m1/test-report.md) | ✅ 骨架完成（板端构建待补） |
| [M2](m2/) | [测试报告](m2/test-report.md)、[架构分层检查](m2/layering-audit.md) | ✅ 通过 |

## 约定

1. **文件夹名与里程碑号一致**：`m2/`、`m3/`……不写日期，日期写在文档里。
2. **文件名固定含义**，方便按节点横向对比：
   - `test-report.md`：该节点的验收测试（环境、用例、结果、缺陷）
   - `layering-audit.md`：该节点的分层解耦检查（方法、证据、差异）
   - 其他文档按内容命名，如 `calibration.md`。
3. **每份文档开头写清**：日期、代码提交、硬件与台架条件。脱离条件的"通过"没有意义。
4. **结论与遗留都写**：未覆盖的项目、观察到的异常，与通过项同等对待。

**测试报告放这里而不是 `tests/`**：报告是给人读的结论，不是能编译运行的东西；`tests/` 只放测试代码。两者的关联由报告里的路径指向 `tests/` 与 `tools/`，不靠目录位置表达。
