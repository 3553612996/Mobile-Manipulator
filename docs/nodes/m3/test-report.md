## 3. 架空台架验收

### 3.1 链路与固件

`proto_loop.py --monitor` 与 `storage_bench.py` 全程 **CRC 错误 0**（单次运行 695 个合法帧）。协议、上报频率（HEARTBEAT 10 Hz、ODOM/WHEEL 约 40 Hz）与文档一致。

### 3.2 方向一致性

`±150‰` 开环占空比下四轮都是"正占空比 → 正轮速"，没有一路反号（A +77/−80、B +66/−75、C +75/−77、D +74/−76 mm/s）。这是 PID 闭环前必须确认的一项，否则积分会把反号放大成飞车。

### 3.3 死区

可靠起转（3/3 起转的最低占空比）：**A 75/67、B 67/75、C 82/80、D 80/100‰**（正/反向）。完整扫描数据见 [pid-tuning.md 3.3](../../bench/pid-tuning.md)。D 轮反向明显偏高，已记录为待检查项。

### 3.4 速度环（200 mm/s，6 s，四轮逐一）

Kp = 5.0 / Ki = 6.0 / Kd = 0：

| 轮 | 稳态 (mm/s) | 误差 | 上升时间 (s) | 超调 | 纹波 (mm/s) |
| --- | --- | --- | --- | --- | --- |
| A 左前 | 195 | −2.5 % | 0.41 | 13.9 % | 29 |
| B 右前 | 195 | −2.6 % | 0.41 | 11.4 % | 33 |
| C 左后 | 195 | −2.3 % | 0.41 | 13.6 % | 26 |
| D 右后 | 195 | −2.4 % | 0.41 | 13.7 % | 29 |

四轮离散度 < 1 %，不需要逐轮整定。60 mm/s 误差 −1.7 ~ −2.9 %，300 mm/s 误差 −2.0 ~ −2.2 %。**以上都在架空（空载）条件下测得**，落地后需要复测。

> **测量条件**：整定时起转补偿还没启用（死区值尚未写盘），所以这组数据是"纯 PID"的表现。补偿在整定之后才落地并落盘，低速档在补偿开启状态下的行为**尚未复测**，列入 6.2。

### 3.5 安全路径（台架）

| 用例 | 结果 |
| --- | --- |
| 断流 200 ms → `0x0202` 上报 + 轮速归零 | PASS |
| 零速指令下轮子不动 | PASS |
| ESTOP → ACK + 事件帧 `0x0501` + 状态 4 | PASS |
| CLEAR_FAULT → 回 IDLE，不自动使能 | PASS |
| 未知命令 → `0x03`，长度错误 → `0x01` | PASS |
| SET_GRIPPER（无夹爪硬件）→ 如实返回 FAILED | PASS |

自动套件结果：**19 PASS / 0 FAIL / 1 SKIP**（跳过项为静态模式下"断流后轮速归零"，该模式轮子本来就不转）。

### 3.6 参数与标定固化

| 项 | 结果 |
| --- | --- |
| `PARAM_SAVE scope=0/1` 连续 4 轮 | 全部 OK，无 BUSY（修复后实测） |
| `REPORT_STORAGE` 标志 | `flags=0x07`（无脏数据 + 参数区有效 + 标定区有效） |
| 序号持久 | `param_seq=31`、`calib_seq=22`（多轮保存递增，未回退） |
| 保存耗时 | 单次 erase+program+回读校验约 60~70 ms，另加 wear 记录约 50 ms，任务内串行，不占控制任务 |

存储台架套件：**64 PASS / 3 FAIL / 2 SKIP**，3 项失败见 6.1，均属本节点范围外。

## 4. 参数与设计选择

| 项 | 当前值 | 依据 | 风险 |
| --- | --- | --- | --- |
| 控制周期 | 10 ms | 1 ms 时一个编码器计数约 40 mm/s，量化太粗 | — |
| 速度量化 | 约 4 mm/s / 10 ms | 24828 counts/mm | 低速段误差占比大 |
| 增益 | Kp 5.0 / Ki 6.0 / Kd 0 | 架空整定（4.3、4.4 节） | 带负载后积分可能偏快 |
| 起转补偿 | A 75/67、B 67/75、C 82/80、D 80/100‰ | 可靠起转实测 | 负载下死区变大，补偿会不足 |
| 增益存储 | 外部 Flash 参数区 | `PARAM_SAVE scope=0` | 编译期默认值 = 实测值，掉参数时行为不突变 |
| 里程计比例 | 24828 counts/mm | 13 线 × 4 倍频 × 90 / (π × 60 mm) | 轮径、打滑未实测 |
| 零速阈值 | 5 mm/s | 低于 10 ms 一个计数约 4 mm/s | 随控制周期/编码器变化需复核 |
| 调参范围 | Kp/Ki ≤ 10.0、Kd ≤ 5.0 | 防止误拖成开关 | — |

## 5. 本轮发现并修复的缺陷

| 缺陷 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 串口零字节、启动卡死 | 上电后 UART 无任何输出，HAL 计时不前进 | ARM_CM3 port 的 `uxCriticalNesting` 初值 `0xAAAAAAAA`，调度器启动前 `taskENTER/EXIT` 不恢复 BASEPRI；队列创建后 `main()` 仍要 `HAL_Delay()`，TIM6 时基被一起屏蔽 | `platform_os_queue_create()` 在调度器未启动时补 `portENABLE_INTERRUPTS()`；SPI 互斥量改为启动后首次使用时创建 |
| 保存后立刻再存被判 BUSY | 主机收到 `REPORT_STORAGE` 后马上发下一次 `PARAM_SAVE`，返回 `0x05` | wear 记录（第二次 4 KB 擦除）在"保存完成"上报之后仍在执行 | wear 记录移到完成上报与回调之后，由存储任务在下次循环刷新；`saves_pending` 也在上报前递减 |
| 一次保存写了两遍 wear 记录 | 保存耗时比预期长约 50 ms | `service_storage_save_blob()` 内部自带 wear 落盘 | 从 save_blob 移除，改由 app 层在回调后触发 |

## 6. 未执行项与遗留

### 6.1 存储台架的 3 项失败（本节点范围外）

| 用例 | 原因 | 处理 |
| --- | --- | --- |
| 至少一个镜像有效（A/B） | 镜像槽归 bootloader/OTA 所有，[flash-layout.md](../../architecture/flash-layout.md) 标注"尚未实现"，固件不上报 IMAGE 标志 | 随 OTA 节点实现 |
| 清空后日志占用下降（0 → 0 B） | app 层还没有运行日志生产者，环本来就是空的 | 日志接入后再验 |
| 导出中再次开始 → BUSY | 空环导出在第二条命令到达前就结束了，断言本身不成立 | 待改：仅在有记录时断言 BUSY |

### 6.2 需要落地或复测的项

| 测试 | 原因 |
| --- | --- |
| 里程计直行 2 m / 原地 360° | 需实际轮胎与场地；届时回填 `counts_per_mm_x1000` |
| 断电重启回读参数 | 写盘已验；重启后读 `STORAGE_QUERY` 确认 seq 不变、flags 干净 |
| 断流/急停的**响应时间** | 已验功能正确，未测 100 ms 级时延 |
| 负载下的死区与增益 | 架空值不能直接用于落地 |
| 运行中调参的副作用 | 已验不串轮；"改增益后无速度尖峰"需带载观察 |
| 起转补偿开启后的低速行为 | 3.4 的数据是在补偿为 0 时测的；补偿值与增益分开落盘，60 mm/s 档需重测一次确认超调没变大 |
| 堵转/过流保护 | 硬件保护未接 |
| D 轮反向死区偏高 | 同一占空比下力矩需求更大，建议检查减速箱/联轴器 |

## 7. 结论与下一步

1. 四轮速度环软件路径完整：目标 → 逆解 → 限幅 → 编码器测速 → PID → 起转补偿 → 占空比；
2. 架空台架完成了 M3 的功能验收：方向、死区、闭环精度、四条安全路径、参数固化；
3. 精度结论只在架空、7.4~7.8 V 条件下成立，落地后按 [pid-tuning.md](../../bench/pid-tuning.md) 复测；
4. 遗留的里程计标定和堵转保护不阻塞 M4（自主导航桥接）：ROS 侧先用计算值跑通链路与行为，落地后一次性标定。

**M3 判定：通过（架空口径）。落地复测清单见 6.2。**
