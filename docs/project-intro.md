# 项目介绍

## 1. 背景

移动机器人能走、能看、能抓，这三件事分开做都不算难；难的是把它们串成一条**能在真实环境里反复跑通、出问题能兜底**的链路。

本项目是一个移动底盘 + 六轴机械臂的具身抓取系统，目标是打通从"听懂一句话"到"把东西抓起来"的完整流程，并按正规项目的标准做工程化：协议有文档、故障有分级、版本可追溯、升级有回滚。

## 2. 目标与范围

**做什么**：

- 激光 SLAM 建图与定位，Nav2 自主导航与避障
- 视觉识别目标并在端侧完成推理（RKNN / NPU）
- 手眼标定 + 逆运动学 + 六轴抓取闭环
- 离线语音指令识别与意图解析
- 固件在线升级（bootloader + APP 分离）
- 故障检测、分级处理与上报

**不做什么**（明确边界，避免摊大饼）：

- 不做三维 SLAM，只用 2D 激光
- 不做多机协作
- 不做通用物体抓取（针对训练过的类别）
- 不做功能安全认证，急停为软件实现

## 3. 系统组成

| 部分 | 硬件 | 软件 |
| --- | --- | --- |
| 上位机 | RK3566（4×A55，0.8 TOPS NPU） | Linux + ROS 2 Humble |
| 下位机 | STM32F103RCT6（72MHz，48KB RAM） | FreeRTOS + C |
| 建图定位 | 2D 激光雷达 | SLAM Toolbox |
| 导航 | — | Nav2 |
| 视觉 | 深度相机 | YOLO 自训练 + RKNN 端侧推理 |
| 机械臂 | 六轴 PWM 舵机 | 逆解 + 轨迹插补 |
| 交互 | 麦克风阵列 | Vosk 离线识别 |

架构细节见[项目框架](architecture/overview.md)。

## 4. 技术选型与理由

| 选择 | 理由 | 放弃的方案及原因 |
| --- | --- | --- |
| ROS 2 | 生态完整，Nav2 / SLAM Toolbox / TF2 都是现成的；节点隔离便于单独重启 | ROS 1 已停止维护 |
| SLAM Toolbox | 位姿图 + 回环，支持序列化与纯定位模式，与 Nav2 同生态 | Gmapping 是粒子滤波，无法回环修正；Cartographer 调参成本高 |
| 2D 激光为主 | 室内结构化环境，2D 足够且算力开销小；IMU 融合抑制里程计漂移 | 视觉 SLAM 在弱纹理、光照变化下不稳定 |
| YOLO + RKNN | RK3566 有 0.8 TOPS NPU，INT8 推理比 CPU 快一个量级 | 云端推理依赖网络、有延迟和隐私问题 |
| Vosk | 完全离线，中文小模型 40~50MB，流式输出 | 云端 ASR 依赖网络；Whisper 模型大，板端跑不动 |
| 双控架构 | Linux 无法保证电机环的微秒级时序 | 单 SoC 方案需要带实时核的芯片（如 i.MX8 + M 核），本板不具备 |
| bootloader + APP 分离 | 支持在线升级，升级失败不影响运行 | 单镜像方案升级失败即变砖 |

## 7. 已知限制

诚实地列出边界，比回避更有价值：

1. **SLAM 用的是现成方案**：SLAM Toolbox 的集成、调参与故障排查，未修改算法本身。
2. **检测网络用的是官方结构**：负责数据采集、训练调参、量化和端侧部署，未做网络结构设计。
3. **抓取面向已知类别**：训练集覆盖的物体，新类别需要重新采集和训练。
4. **无功能安全认证**：急停为软件实现，商用需要独立的硬件安全回路。
5. **无远程诊断**：故障需现场读取日志。
