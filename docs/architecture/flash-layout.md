# 外部 Flash 存储布局（W25Q64，8 MB）

> **状态：布局与协议定义完成，未实现代码。** 本文只定"哪块区域放什么、记录长什么样、谁能写、掉电怎么办"，不含代码。第 11 节是已定的接口与遗留项，协议侧格式见 [protocol.md](protocol.md) 5.5 节。

相关文档：[项目框架](overview.md) · [软件结构](software-design.md) · [串口协议](protocol.md) · [四轮整定记录](../bench/pid-tuning.md)

---

## 1. 已定的决策

| 决策 | 取值 | 理由 |
| --- | --- | --- |
| 芯片 | W25Q64JV，8 MiB | 板上现有 |
| 几何 | 256 B 页 / 4 KB 扇区 / 64 KB 块（2048 / 128） | 擦除最小单位是**扇区**，写最小单位是**页**，跨页写会回卷 |
| 总线 | SPI2：CS=PB12，SCK=PB13，MISO=PB14，MOSI=PB15 | SPI1 的 PA5~PA7 与 TIM3 电机 PWM 冲突；这组脚与商家驱动一致，`.ioc` 里空着 |
| 升级方式 | 外部存整包镜像，内部单 App 分区 | 外部掉电丢失只损失"待升级的镜像"，运行中的 App 在内部 Flash 不受影响；回滚靠外部保留上一版 |
| 参数持久化 | A/B 双副本 + 递增序号 + CRC32 | 任意时刻至少一份可读；写新副本时旧副本不动 |
| 额外分区 | 故障事件环、运行日志环、HardFault 现场、擦写寿命统计 | 现场排障需要的全部信息 |
| 地址权威 | 本文 + Flash 内的分区表（两份） | 分区表用于运行时校验；本文是分区表损坏时的编译期兜底 |

**不采用商家源码里的地址表**（`0x000000` 字库、`0x043000` 系统配置、`0x050000` 图片）：那是另一个产品的布局，直接沿用会和我们的区域重叠。

## 2. 介质约束（决定了记录格式）

| 约束 | 后果 |
| --- | --- |
| 擦除单位 4 KB | 同一扇区里的任何一次修改都要整扇区擦掉，所以"一条记录一个扇区"或"顺序追加" |
| 写单位 256 B，**不可跨页** | 记录长度按 4 B 对齐，写函数按页切分；BSP 已约定跨页写返回失败 |
| 只能 1→0 | 同一位置不能改写，只能往后追加；计数器用"每次写一个新槽"的方式 |
| 4 KB 扇区擦除 45 ms 典型 / 400 ms 最大 | **不能在 10 ms 控制任务里擦写**，存储放在独立低优先级任务 |
| 页编程 0.7 ms 典型 / 3 ms 最大 | 同上 |
| 擦写寿命 10 万次/扇区 | 环形结构 + 写频率预算（第 7 节） |
| 数据保持 20 年 | 出厂信息、标定这类极少写的数据可以放心长期保存 |

## 3. 总体地图

```
块号        地址          大小        区域
──────────────────────────────────────────────────────────────
  0    0x000000     64 KB   引导元数据（分区表、引导控制块、启动计数）
  1-2  0x010000    128 KB   固件镜像槽 A
  3-4  0x030000    128 KB   固件镜像槽 B
  5    0x050000     64 KB   参数区（A/B 各 32 KB）
  6    0x060000     64 KB   标定区（A/B 各 32 KB）
  7    0x070000     64 KB   崩溃现场（16 槽 × 4 KB）
 8-9   0x080000    128 KB   故障事件环（32 扇区）
10-23  0x0A0000    896 KB   运行日志环（224 扇区）
 24    0x180000     64 KB   擦写寿命统计（A/B）
25-126 0x190000    6.375 MB 预留
127    0x7F0000     64 KB   出厂信息（序列号、板号、生产日期）
──────────────────────────────────────────────────────────────
       0x800000     8 MiB
```

| # | 区域 | 起始 | 大小 | 写频率 | 写入者 |
| --- | --- | --- | --- | --- | --- |
| 0 | 引导元数据 | `0x000000` | 64 KB | 每次升级、每次启动 | **仅 bootloader** |
| 1 | 镜像槽 A | `0x010000` | 128 KB | 每次 OTA | bootloader（App 只读） |
| 2 | 镜像槽 B | `0x030000` | 128 KB | 每次 OTA | bootloader |
| 3 | 参数区 | `0x050000` | 64 KB | 用户保存时 | App 存储任务 |
| 4 | 标定区 | `0x060000` | 64 KB | 标定完成时 | App 存储任务 |
| 5 | 崩溃现场 | `0x070000` | 64 KB | 崩溃时 | HardFault 处理（受限上下文） |
| 6 | 故障事件环 | `0x080000` | 128 KB | 故障发生时 | App 存储任务 |
| 7 | 运行日志环 | `0x0A0000` | 896 KB | 持续 | App 存储任务 |
| 8 | 寿命统计 | `0x180000` | 64 KB | 每 100 次擦除 / 关机 | App 存储任务 |
| 9 | 预留 | `0x190000` | 6.375 MB | — | — |
| 10 | 出厂信息 | `0x7F0000` | 64 KB | 产线一次 | 产线工具 |

**为什么镜像槽在两个大块（128 KB）后面才开始参数区**：OTA 镜像擦除以 64 KB 块为主（快，且不会误擦别的东西），镜像槽按块对齐能把"整片擦除"限制在这 4 个块里。参数、标定、日志都从块边界起步，任何一次块擦除都不会碰到隔壁。

## 4. 通用记录头（32 B）

除镜像头和日志记录外，所有持久记录都用这个头，字段顺序固定：

| 偏移 | 类型 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | `u32` | `magic` | 每类记录一个固定值，见下表 |
| 4 | `u16` | `layout_ver` | 记录格式版本，当前 1 |
| 6 | `u16` | `flags` | 通用位：bit0=有效，其余按区域定义 |
| 8 | `u32` | `seq` | 同一副本每次写 +1；A/B 比较用 |
| 12 | `u32` | `payload_len` | 负载字节数（不含头、不含尾部 CRC） |
| 16 | `u32` | `crc32` | 覆盖 `magic..payload` 的全部字节 |
| 20 | `u32` | `ts` | 写入时刻（Unix 秒，无 RTC 时为开机上电秒） |
| 24 | `u16` | `writer` | 写入者：0=bootloader，1=app，2=产线工具 |
| 26 | `u16` | `reserved0` | 0xFFFF |
| 28 | `u32` | `reserved1` | 0xFFFFFFFF |

**CRC32 覆盖范围包含 `seq` 和 `payload_len`**：半写记录必然 CRC 失败，不需要额外的"提交标志"。这是整个掉电安全的基础。

各区 magic：

| 区域 | magic | 助记 |
| --- | --- | --- |
| 分区表 | `0x4C42504E` | `'LBPN'` layout partition |
| 引导控制块 | `0x424F4F54` | `'BOOT'` |
| 参数 | `0x50415241` | `'PARA'` |
| 标定 | `0x43414C49` | `'CALI'` |
| 寿命统计 | `0x57454152` | `'WEAR'` |
| 崩溃现场 | `0x43524153` | `'CRAS'` |
| 出厂信息 | `0x46414354` | `'FACT'` |
| 镜像头 | `0x52494D47` | `'RIMG'` |
| 故障记录 | `0x5AF5`（16 位） | 定长 32 B |
| 日志记录 | `0x5BF5`（16 位） | 变长 |

## 5. 逐区域定义

### 5.1 引导元数据（块 0）

| 偏移 | 大小 | 内容 |
| --- | --- | --- |
| `0x000000` | 4 KB | 分区表 A |
| `0x001000` | 4 KB | 分区表 B |
| `0x002000` | 4 KB | 引导控制块 A |
| `0x003000` | 4 KB | 引导控制块 B |
| `0x004000` | 4 KB | 启动计数区（1024 × `u32`，写满才擦） |
| `0x005000` | 44 KB | 预留 |

#### 分区表

通用头 + 最多 16 条：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name[8]` | `char` | `"PARAM"`、`"CALIB"`、`"LOG"`、`"FAULT"`、`"CRASH"`、`"WEAR"`、`"IMG_A"`、`"IMG_B"`、`"FACT"` |
| `offset` | `u32` | 起始地址 |
| `size` | `u32` | 字节数 |
| `flags` | `u32` | bit0=bootloader 独占，bit1=只读，bit2=只追加 |

启动时 App 读两份分区表，取 CRC 有效且 `seq` 大者。**校验失败不阻止运行**：退回本文第 3 节的编译期常量表，同时上报 `0x0604`。分区表与代码不一致时（比如刷了旧固件）拒绝执行任何写入，避免写错地址。

#### 引导控制块

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `boot_status` | `u8` | 0=新镜像未确认，1=已确认可回滚点 |
| `active_slot` | `u8` | 0=槽 A，1=槽 B |
| `previous_slot` | `u8` | 上一版所在槽（回滚来源） |
| `upgrade_request` | `u8` | 1=App 请求升级，bootloader 启动时处理 |
| `boot_attempts` | `u32` | 当前镜像连续启动次数，App 确认后清零 |
| `last_image_seq` | `u32` | 上次安装的镜像序号 |
| `last_image_crc` | `u32` | 上次安装的镜像 CRC |

**回滚策略**：bootloader 把镜像装进内部 Flash 后置 `boot_status=0`、`boot_attempts+1`。App 稳定运行 30 s 后写 `boot_status=1`。若连续 3 次启动 `boot_status` 仍为 0，bootloader 从 `previous_slot` 重新安装上一版。**任何时刻不允许两个槽都无效**——装新镜像前先确认另一槽有效，否则拒绝升级（沿用 [software-design.md](software-design.md) 第 187 行的约束）。

#### 启动计数区

1024 个 `u32` 槽，启动时从前往后找第一个 `0xFFFFFFFF`，写 `0x00000001` 进去；写满 1024 个才擦一次，擦除代数记在引导控制块里。**为什么不用"读-改-写"**：擦除一个扇区需要 45 ms，每次启动都擦会拖慢启动并快速消耗寿命；追加写只需要一次页编程（<1 ms），1000 次启动才擦一次。

### 5.2 固件镜像槽（块 1~4）

每个槽 128 KB：

| 槽内偏移 | 大小 | 内容 |
| --- | --- | --- |
| `+0x0000` | 64 B | 镜像头（**最后写**） |
| `+0x0040` | 960 B | 0xFF 填充 |
| `+0x0400` | ≤ 127 KB | `.bin` 原文（内部 Flash 从 App 起始地址起逐字节对应） |

镜像头：

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0 | `u32` | `magic` = `'RIMG'` |
| 4 | `u16` | `hdr_ver` = 1 |
| 6 | `u16` | `hdr_len` = 64 |
| 8 | `u32` | `image_len` |
| 12 | `u32` | `image_crc32` |
| 16 | `u32` | `image_seq`（每次构建/升级 +1） |
| 20 | `u8×3` | `ver_major/minor/patch` |
| 23 | `u8` | `flags`（bit0=有效） |
| 24 | `u32` | `build_unix_s` |
| 28 | `u8[8]` | `git_hash` 前 8 字节 |
| 36 | `u16` | `board_id` |
| 38 | `u16` | `reserved` |
| 40 | `u32` | `entry_addr` |
| 44 | `u32` | `hdr_crc32` |
| 48 | 16 B | 预留 |

**写顺序**：擦除目标槽（64 KB 块擦）→ 写载荷 → 回读整段校验 CRC → 最后写镜像头。头在，就说明载荷完整；头没写或 CRC 错，槽视为空。所以升级过程中断电任意时刻，两个槽至少有一个仍然有效。

**容量约束**：镜像槽 128 KB，内部 App 区必须 ≤ 128 KB。构建脚本检查 `.bin` 超过 128 KB 时直接失败，不允许"先烧进去再发现"。

### 5.3 参数区（块 5）

| 偏移 | 大小 | 内容 |
| --- | --- | --- |
| `0x050000` | 32 KB | 副本 A（8 扇区，有效记录在第 1 扇区，其余预留） |
| `0x058000` | 32 KB | 副本 B |

参数负载（`u16 layout_ver` 之外的字段，全部小端）：

| 字段 | 类型 | 单位/范围 | 当前来源 |
| --- | --- | --- | --- |
| `wheel_pid_kp[4]` | `i32` | ×1000 | 5.0 → 5000（整定值） |
| `wheel_pid_ki[4]` | `i32` | ×1000 | 6.0 → 6000 |
| `wheel_pid_kd[4]` | `i32` | ×1000 | 0 |
| `max_vx / max_vy / max_wz` | `i16` | mm/s、mm/s、mrad/s | 限幅 |
| `max_wheel_mm_s` | `i16` | mm/s | 单轮上限 |
| `cmd_timeout_ms` | `u16` | ms | 200 |
| `test_duty_max_permille` | `u16` | ‰ | 400 |
| `deadzone_comp_enable` | `u8` | 0/1 | 默认 0（见第 11 节） |
| `log_level` | `u8` | 0~3 | 1 |
| `save_count` | `u32` | — | 每保存一次 +1 |

**用整数 ×1000 而不是 float**：跨编译器和跨版本的结构布局一致，CRC 不会因为浮点格式差异而误判。上层要 float 时在加载后转换。

写入流程：

1. 选**非活动副本**（`seq` 较小的那份）；
2. 擦除该副本第 1 扇区（期间活动副本不动，掉电只损失这次保存）；
3. 写记录头 + 负载；
4. 回读并重算 CRC32，**不一致则丢弃本次写入**，旧副本继续有效，上报 `0x0603`；
5. 成功后才更新 RAM 里的"当前活动副本"。

上电加载：读两份，过滤 `magic`/CRC/`layout_ver` 不合格的，取 `seq` 大者；都无效 → 用 `app_robot_config.h` 的编译期值，上报 `0x0601`，并把参数标记为"未固化"（此时 `REPORT_STATUS` 的参数标志位应体现在位上，见第 9 节）。

**为什么参数和标定分开**：恢复出厂设置只清参数，不动标定。混在一个区里，一次"恢复默认"会把轮径、编码器比例、关节零点全部抹掉——那是需要重新上标定台的代价。

### 5.5 崩溃现场（块 7）

16 个 4 KB 槽，槽 `n` 位于 `0x070000 + n × 0x1000`。写入位置 = `seq % 16`；该槽属于 16 次之前，擦除后写入即可。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 通用头 | 32 B | `magic='CRAS'`，`seq` 递增 |
| `pc / lr / psr / sp` | `u32×4` | 异常帧 |
| `r0~r3 / r12 / xpsr` | `u32×6` | 压栈寄存器 |
| `cfsr / hfsr / mmfar / bfar` | `u32×4` | SCB 故障状态 |
| `app_ver / git_hash[8]` | — | 崩溃的是哪个固件 |
| `task_name[8]` | `char` | 当前任务 |
| `stack[512]` | `u8` | 崩溃栈窗口 |
| `crc32` | `u32` | **单独放在记录最后一个页里，最后写** |

**为什么要单独放一页**：崩溃写入过程本身可能再次断电或再次 HardFault。把 CRC 放在独立的一页、最后写，只要 CRC 没写上去，这次记录就作废，不会出现"半个现场被当成有效现场"。

HardFault 处理里只做这一件事，写完立即复位。栈窗口放在最后，因为它是调试价值最高但最可能越界读取的部分（读到的可能本身就是坏栈，但总比没有好）。

### 5.6 故障事件环（块 8~9，128 KB）

32 个扇区，每扇区：

| 偏移 | 大小 | 内容 |
| --- | --- | --- |
| `+0x0000` | 16 B | 扇区头：magic `0x5EC7`、`sector_seq`、首条记录偏移、1 字节状态 |
| `+0x0010` | 4080 B | 127 条 × 32 B 记录 |

单条记录 32 B：

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0 | `u16` | magic `0x5AF5` |
| 2 | `u8` | level（1=WARN, 2=ERROR, 3=FATAL） |
| 3 | `u8` | module（1=底盘, 2=通信, 3=机械臂, 4=电源, 5=急停, 6=存储…） |
| 4 | `u32` | `ts` |
| 8 | `u16` | fault code（`protocol.md` 第 8 节） |
| 10 | `u8` | 系统状态（IDLE/MANUAL/AUTO/ESTOP/FAULT） |
| 11 | `i8` | 温度 ℃ |
| 12 | `u16` | 电池 mV |
| 14 | `u16` | 预留 |
| 16 | `u32` | `context0`（例如出故障那一轮的轮速） |
| 20 | `u32` | `context1` |
| 24 | `u32` | `seq`（全局递增） |
| 28 | `u16` | CRC16（协议同一套 CCITT，见 `shared/crc`，覆盖偏移 0~27） |
| 30 | `u16` | 尾部标记 `0xA55A` |

写满一个扇区后擦下一个扇区再写。容量约 127 × 32 = **4064 条**。故障是稀疏事件，这个容量相当于数年。

### 5.7 运行日志环（块 10~23，896 KB）

224 个扇区，每扇区同样以 16 B 扇区头开始，之后是变长记录：

| 偏移 | 类型 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | `u16` | magic `0x5BF5` | |
| 2 | `u8` | level | 0=DEBUG, 1=INFO, 2=WARN, 3=ERROR |
| 3 | `u8` | tag | 模块号，同故障记录 |
| 4 | `u32` | `ts` | |
| 8 | `u16` | `len` | 负载字节数，≤ 240 |
| 10 | `u16` | crc16 | 覆盖头（除本字段）+ 负载 |
| 12 | `u32` | `seq` | |
| 16 | `len` | payload | ASCII 文本，4 B 对齐填充 |

**为什么是文本**：日志的第一读者是人。二进制日志省空间，但每次排障都要先写解析器。896 KB 够放约 9000 条 100 B 的记录，文本更划算。

写入策略：

- 只记**事件**，不记周期数据（轮速、电流等走串口上报，不进 Flash）；
- 同一 `tag + code` 在 1 s 内重复只记一次（限流），防止故障抖动把环刷满；
- 环满即覆盖最旧扇区，不报故障，但要在寿命统计里记 `log_wrap_count`。

### 5.8 擦写寿命统计（块 24）

| 偏移 | 大小 | 内容 |
| --- | --- | --- |
| `0x180000` | 4 KB | 副本 A |
| `0x181000` | 4 KB | 副本 B |

| 字段 | 说明 |
| --- | --- |
| `boot_total` | 累计启动次数（来自启动计数区 + 代数） |
| `erase_count[6]` | 参数、标定、镜像、故障环、日志环、崩溃 六类区域各自的累计擦除次数 |
| `log_bytes_total` | 日志累计写入字节数（用于估算真实写速率） |
| `log_wrap_count` | 日志环回卷次数 |
| `last_write_ts` | 上次写入时间 |
| `sector_erase[224]` | 日志环逐扇区擦除次数（`u16`，取饱和） |

写入时机：每累计 100 次擦除、或每次正常关机前。**不能每写一条日志就更新**——那会把统计区自己写成新的磨损点。逐扇区计数在 RAM 里维护，定期落盘，掉电最多丢 100 次以内的增量，作为统计足够。

### 5.9 出厂信息（块 127）

与分区表同构，`magic='FACT'`，最多 16 条记录按扇区顺序追加，产线写一次：

| 字段 | 说明 |
| --- | --- |
| `serial[16]` | 序列号，ASCII |
| `board_rev` | 板卡版本 |
| `mfg_date` | 生产日期（YYYYMMDD） |
| `pcb_batch[8]` | 批次 |
| `factory_test_result` | 产线测试结果码 |

运行期固件对这块**只读**，分区表里标 `bit1=只读`。出厂信息是保修和追溯的唯一依据，任何情况下不允许运行期擦除。

## 6. 写入者与并发

| 场景 | 执行者 | 说明 |
| --- | --- | --- |
| 保存参数 | App `appStorage` 任务 | 通信任务收到 `SET_PARAM` 只改 RAM 并置脏标志 |
| 标定写入 | App `appStorage` 任务 | 由专用标定命令触发，写前确认底盘失能 |
| 故障记录 | App `appStorage` 任务 | 故障模块只入队，不在中断里写 Flash |
| 日志 | App `appStorage` 任务 | 其他任务调 `storage_log()` 只是入队 |
| 崩溃现场 | HardFault 处理 | 唯一的例外：直接阻塞写，不能等任务调度 |
| 升级镜像 | bootloader | App 只负责把镜像数据收进外部槽（复用同一套 BSP 写函数） |
| 寿命统计 | App `appStorage` 任务 | 定期 |

**一个写者原则**：除了 bootloader 和 HardFault，所有对外部 Flash 的擦写都走 `appStorage` 任务。理由和 PID 一样——两个任务同时擦同一个扇区，结果是两份数据都坏。任务间用请求队列，队列元素是"区域 + 负载"，不是指针。

**任务优先级**：`appStorage` 放在 `appComm` 之下、`appIdle` 之上，栈 ≥ 512 B（记录缓冲 + 栈）。擦除期间（最长 400 ms）它被阻塞，但控制任务和通信任务照常跑；这要求所有 Flash 访问都是**非阻塞状态机或纯轮询 BUSY 位**，不能持有关键互斥锁。

## 7. 寿命预算

W25Q64 标称 10 万次擦除/扇区。环形区的寿命公式：

```
可写总字节 ≈ 环大小 × 100000
寿命(年)   ≈ 可写总字节 / (平均写速率 × 365 × 24 × 3600)
```

| 区域 | 环/扇区大小 | 平均写速率预算 | 理论寿命 |
| --- | --- | --- | --- |
| 运行日志环 | 896 KB | **200 B/s** | ≈ 14 年 |
| 运行日志环 | 896 KB | 1 KB/s（上限告警线） | ≈ 2.8 年 |
| 故障事件环 | 128 KB | 稀疏事件 | 数十年 |
| 崩溃现场 | 64 KB | 每次崩溃 1 个扇区 | — |
| 参数区 | 4 KB 有效扇区 ×2 | 10 次保存/天 | ≈ 54 年 |
| 参数区 | 同上 | 100 次保存/天 | ≈ 5.5 年 |
| 启动计数 | 4 KB（1024 槽） | 10 次启动/天 | 每 102 天擦一次，可忽略 |

**结论**：日志是唯一的磨损热点，设计约束是**平均 ≤ 200 B/s**（约每秒 1 条 100 B 记录）。超过 1 KB/s 要在代码评审里拦下来，或者把日志环扩容到预留区。

参数区每天保存 100 次以上属于异常用法（正常是标定/调参时保存），5.5 年也够；如果将来出现"每次改滑条都保存"的用法，改成副本内 8 扇区顺序追加即可 ×8，格式不用变（`seq` 在记录头里）。

## 8. 掉电与损坏恢复

| 时刻 | 掉电后果 | 恢复 |
| --- | --- | --- |
| 参数：擦除非活动副本中 | A 副本仍在，本次保存丢失 | 下次保存重试 |
| 参数：写记录中 | 新记录 CRC 错 → 视为无效 | 用旧副本 |
| 参数：回读校验中 | 同上 | 同上 |
| 镜像：擦除槽中 | 该槽无效，另一槽和内部 App 都完好 | 重新升级 |
| 镜像：写载荷中 | 无镜像头 → 空槽 | 重新升级 |
| 镜像：写头时 | 头 CRC 错 → 空槽 | 重新升级 |
| 镜像：bootloader 拷到内部 Flash 中 | 内部 App 半写，无法启动 | bootloader 检测内部 App CRC 失败 → 重装上一版（另一槽） |
| 日志/故障：写记录中 | 该条 CRC 错，扫描在此停止 | 上一条为最新 |
| 崩溃现场：写记录中 | 无 CRC → 无效槽 | 丢掉本次现场 |
| 寿命统计：写中 | 上一次统计仍有效 | 丢 ≤100 次增量 |

启动扫描顺序（`appStorage` 初始化）：

1. 读分区表 A/B → 校验；失败用编译期表并置 `0x0604`；
2. 读参数 A/B → 校验 → 加载或回退编译期值（`0x0601`）；
3. 读标定 A/B → 校验 → 加载或回退编译期值（`0x0602`）；
4. 扫描日志环与故障环尾指针（从当前扇区头开始往后读到第一条无效记录）；
5. 检查是否有未读的崩溃现场 → 通过日志命令上报"有崩溃记录"（不自动清）。

**扫描的代价**：一个扇区最多 256 条记录，最坏情况扫 224 个扇区。为了不让启动变慢，扇区头里存"最后写入位置"，正常情况只读当前扇区即可；只有扇区头 CRC 坏时才退化为整环扫描。

## 9. 与协议 / bootloader / OTA 的接口

每个区域对应哪条协议命令（线上格式见 [protocol.md](protocol.md) 5.5 节）：

| 区域 | 读 | 写 |
| --- | --- | --- |
| 参数区 | 上电自动加载 | `PARAM_SAVE(0)` / `PARAM_RESET(0)` |
| 标定区 | 上电自动加载 | `PARAM_SAVE(1)` / `PARAM_RESET(1)`（要求底盘失能） |
| 状态与寿命 | `STORAGE_QUERY` → `REPORT_STORAGE` | — |
| 运行日志 / 故障环 | `LOG_EXPORT` → `REPORT_LOG` | 运行时自动记录；`LOG_CLEAR` 清除 |
| 崩溃现场 | `CRASH_READ` → `REPORT_CRASH` | HardFault 自动写入 |
| 镜像槽 | bootloader 启动时读 | OTA 命令 `0x20~0x24`（见 overview.md） |

### 9.1 升级流程

```
上位机 →(串口 0x20~0x24)→ App ──写──► 镜像槽 B
                                  │
                                  ├─ 校验整包 CRC
                                  └─ 置 upgrade_request=1，写引导控制块，复位
                                          │
                                     bootloader 启动
                                          ├─ 读引导控制块（A/B）
                                          ├─ 选镜像槽中 seq 更大且有效者
                                          ├─ 拷贝到内部 App 区
                                          ├─ 校验内部镜像 CRC
                                          └─ 跳转
```

- **内部 Flash 划分（待 bootloader 实现时确认）**：`0x08000000` 起 16 KB 给 bootloader，`0x08004000` 起 240 KB 给 App；镜像槽 128 KB 是更严格的约束。
- **App 不写块 0、不写镜像槽的头部**：分区表里标 `bit0=bootloader 独占`，BSP 层 API 检查写入者身份，防止将来有人图省事从 App 直接改镜像。
- **升级期间底盘必须失能**：`OTA_BEGIN` 时强制 `SET_ENABLE(0)` 并进入升级状态，避免写 Flash 的延时影响控制环。
- **参数在升级后保留**：参数/标定区与镜像无关，升级不动。`layout_ver` 变化导致结构不兼容时，由 App 加载时拒绝并回退默认值，同时上报 `0x0601`。

## 10. 版本与兼容规则

1. **记录格式升级**：只能在尾部加字段（`layout_ver` 次版本 +1），旧字段偏移和类型永远不动；删改字段属于大版本，加载时视为无效并回退默认值。
2. **区域地址在量产后永不改变**：新区域只能从预留区划分，并追加到分区表。改旧区域基地址等于让所有已出货设备的参数全部失效。
3. **分区表 `layout_ver` 与固件不匹配时拒绝写入**，但不拒绝启动——宁可功能受限，不能变砖。
4. **本文与代码同步**：实现存储服务时，地址表和记录结构必须与本文一致；改动先改本文，再改代码，同一个提交。

## 11. 已定的接口与遗留项

以下 7 项已拍板，协议部分已写入 [protocol.md](protocol.md)：

| # | 结论 |
| --- | --- |
| 1 | 保存参数用 `PARAM_SAVE 0x08`（`scope` 0/1/2），`SET_PARAM` 只写 RAM |
| 2 | 日志导出用 `LOG_EXPORT 0x0B` → `REPORT_LOG 0xC9`，限速 20 Hz；崩溃现场用 `CRASH_READ 0x0C` → `REPORT_CRASH 0xCA` 分片 |
| 3 | 死区值、编码器比例、轮径、轮向放**标定区**；参数区只放补偿开关与增益 |
| 4 | 日志默认 INFO，周期数据（轮速/电流）不入 Flash，平均写速率预算 200 B/s |
| 5 | 新增故障码 `0x0601~0x0604`，已进 `protocol.md` 第 8 节 |
| 6 | 镜像只做 CRC32，不签名——本项目无恶意刷写威胁模型，签名会引入密钥管理成本 |
| 7 | SPI2 启用 DMA，擦除用轮询 `BUSY`；实现驱动时同步改 `.ioc` |

仍然遗留、不影响开工的三项：

| # | 问题 | 当前处理 |
| --- | --- | --- |
| 1 | 内部 bootloader 大小（暂定 16 KB） | 实现 bootloader 工程时确认；上限由镜像槽 128 KB 反向约束 |
| 2 | 参数是否需要"设备序列号/写入人" | 暂不做；出厂信息区已留 SN，参数记录头留了 `writer` 字段 |
| 3 | 多台设备统一参数的分发方式 | 暂不做，先保证单机可保存/导出 |

**一句话总结**：块 0 归 bootloader（分区表 + 引导控制 + 启动计数），4 个块装两版镜像，一块参数、一块标定各自 A/B，一块崩溃现场，128 KB 故障环，896 KB 日志环，一块寿命统计，尾部一块出厂信息——所有持久记录都是"带序号和 CRC 的自描述记录"，任何一次写入中途掉电都只丢这一次。
