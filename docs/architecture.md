# 项目框架

系统级视角：两块控制器怎么分工、硬件怎么连、软件怎么分层、数据怎么流、怎么部署。

相关文档：[软件结构](software-design.md) · [串口协议](protocol.md)

---

## 1. 系统总览

移动底盘 + 六轴机械臂 + 深度相机 + 2D 激光雷达 + 麦克风阵列。

```
┌───────────────────────────────────────────────────────────────┐
│  RK3566  ·  Linux + ROS 2  ·  4×A55 @1.8GHz / 0.8 TOPS NPU    │
│                                                               │
│   SLAM 建图定位    Nav2 路径规划    YOLO+RKNN 视觉    Vosk 语音  │
│   任务状态机       日志与监控       故障上报                     │
└───────────────────────────┬───────────────────────────────────┘
                            │ UART 921600 8N1
                            │ 下行：速度 / 关节 / 使能 / 参数 / 升级
                            │ 上行：里程计 / 关节 / 状态 / 事件
┌───────────────────────────┴───────────────────────────────────┐
                            │
│  STM32F103RCT6 · FreeRTOS · 72MHz / 48KB RAM / 256KB Flash    │
│                                                               │
│   电机 PID 闭环    编码器测速    六轴关节插补    安全保护        │
│   协议解析         故障检测      看门狗                         │
└───────────────────────────────────────────────────────────────┘
        │                    │                    │
   电机驱动 + 编码器     舵机总线            电源 / IMU
```

### 为什么分成两块

| | RK3566 | STM32F103RCT6 |
| --- | --- | --- |
| 任务性质 | 计算密集、可容忍几十~几百毫秒延迟 | 简单但要求微秒级确定性 |
| 失效后果 | 功能降级，可重启恢复 | 电机失控 |
| 调度 | 分时操作系统，抖动毫秒级 | FreeRTOS 抢占式，抖动微秒级 |
| 算力 | 4 核 + NPU | 72MHz，48KB RAM |

**核心判断**：Linux 是分时系统，控制环路的时序无法保证；而 SLAM、视觉推理、语音又只有 Linux 能承载。所以按**实时性等级**切分，而不是按"哪个更强"切分。

MCU 侧还承担最后一道保护：**通信断流 200 ms 主动停车**。这条不能放在 Host 侧，因为 Host 正是可能出故障的那一端。

## 2. 硬件拓扑

```
12V 电池
 ├──► 降压 5V/3A ──► RK3566
 ├──► 降压 5V/10A ─► 舵机（**独立一路**，六轴同时动作瞬时电流可达 10A）
 └──► 电机驱动板 ──► 四路电机（含编码器）
                        │ PWM + 编码器
                     STM32F103RCT6
                        ├── UART ◄──► RK3566
                        ├── 六路 GPIO ──► 六轴 PWM 舵机（软件 PWM）
                        ├── ADC ──► 电池分压监测
                        └── I2C ──► IMU

RK3566
 ├── USB ──► 深度相机
 ├── USB ──► 麦克风阵列
 └── UART/USB ──► 2D 激光雷达
```

**接线约束**：

1. **所有设备必须共地**，否则串口出现随机乱码——这是板间通信第一大坑。
2. **舵机独立供电**，与大电流电机分开走线，必要时加磁环。共电源会导致 RK3566 欠压重启。
3. 串口线远离电机动力线，必要时用屏蔽线。

## 3. 软件分层

### 3.1 RK3566 侧

| 层 | 内容 | 说明 |
| --- | --- | --- |
| 应用层 | `robot_task` | 任务状态机，编排导航、抓取、语音 |
| 功能层 | `robot_vision` `robot_arm` `robot_speech` | 视觉推理、机械臂解算、语音识别 |
| 中间件 | Nav2 / SLAM Toolbox / TF2 | 开箱组件，只做配置与集成 |
| 桥接层 | `robot_base` | ROS 2 话题 ↔ 串口帧，是唯一的硬件边界 |
| 系统层 | systemd / 日志 / 监控 | 进程托管、日志轮转、资源监控 |

**关键约束**：只有 `robot_base` 和 `robot_arm` 知道串口的存在。上层节点只跟 ROS 2 接口打交道，这样任何节点都可以在 PC 上跑仿真、录包回放。

### 3.2 STM32 侧

```
┌──────────────────────────────────────────────┐
│  main.c       HAL 初始化 → 外设 → osKernelStart│
├──────────────────────────────────────────────┤
│  tasks        control / motion / proto /     │
│               report / app                   │
├──────────────────────────────────────────────┤
│  control      电机 PID、编码器测速、PWM 输出  │
│  motion       六轴轨迹插补、限位与奇异检查     │
│  protocol     帧解析、组帧、CRC、序号去重      │
│  safety       通信超时、过流、故障码管理       │
├──────────────────────────────────────────────┤
│  bsp          UART / PWM / TIM / ADC / EXTI  │
├──────────────────────────────────────────────┤
│  FreeRTOS     内核、队列、信号量、任务通知     │
├──────────────────────────────────────────────┤
│  HAL          STM32 HAL（CubeMX 生成）        │
└──────────────────────────────────────────────┘
```

**分层规则**：上层可以调下层，下层不许回调上层。`protocol.c` 只依赖 `shared/`，不依赖 HAL 和 FreeRTOS——这样它能在 PC 上用 gcc 单独编译测试。

**为什么用 FreeRTOS 而不是裸机主循环**：裸机方案里所有事情挤在一个循环，靠标志位分时，任何一处阻塞都会拖慢整个系统。项目里有 5 类节奏完全不同的逻辑（1 ms 控制、10 ms 插补、事件驱动的协议、20 ms 上报、按需的任务状态机），用 RTOS 按优先级调度比手工排时间片清晰得多，也更容易在面试里讲清楚每个模块的时序保证。

**代价**：中断优先级配置错了会随机 HardFault（见[软件结构 · 并发](software-design.md#6-并发与实时性)），栈溢出比裸机难查。所以规范里对中断和栈有硬性要求。

## 4. 关键数据流

### 4.1 启动流程

```
上电
 └─► bootloader
      ├─ 检查 RTC 备份寄存器是否等于升级 magic
      │   ├─ 是 → 进入 DFU 模式，等待升级帧
      │   └─ 否 ↓
      └─ 校验 APP 栈顶指针合法性（必须落在 RAM 范围）
           ├─ 非法 → 停在 DFU 模式
           └─ 合法 → 关中断、复位外设、设 MSP、跳转 APP
```

APP 启动后由 systemd（RK3566 侧）拉起 ROS 2 节点，顺序为：串口桥接 → 定位/建图 → 导航 → 视觉 → 任务。

### 4.2 速度控制闭环

```
Nav2 / 遥控
   │ /cmd_vel (50Hz)
   ▼
base_bridge ──差分运动学──► 左右轮速
   │
   ├─ 组帧 SET_VELOCITY ──► 串口 ──► STM32
   │                                   │ control_task 1ms：读编码器、算 PID、更新 PWM
   │                                   │
   │ /odom  ◄── REPORT_ODOM (50Hz) ◄───┘
   ▼
定位 / 里程计融合
```

**时间预算**（STM32 侧，按下表的任务优先级排布）：

| 任务 | 周期 | 单次预算 | 超时的表现 |
| --- | --- | --- | --- |
| `control_task` 编码器采样 + 速度环 PID | 1 ms | < 100 µs | 电流环抖动、电机啸叫 |
| `motion_task` 关节插补 + 限位检查 | 10 ms | < 500 µs | 轨迹不平滑、关节顿挫 |
| `proto_task` 帧解析 | 事件驱动 | < 20 µs / 帧 | 指令延迟 |
| `report_task` 状态上报组帧 | 20 ms | < 200 µs | 上位机数据过期 |
| `app_task` 状态机、参数、故障处理 | 事件驱动 | 不限 | 响应变慢，但不影响控制 |

**1 ms 控制周期是硬指标**：`control_task` 用 `vTaskDelayUntil` 保证周期，优先级设为最高。其余任务即使卡住，也不会影响控制环——这正是用 RTOS 的意义。

**急停不走任务**：急停按钮接 EXTI 中断，中断里**直接关闭 PWM 输出**，不等任何任务调度。任务层的状态机只负责后续的故障上报与恢复。安全动作不能排队。

### 4.3 一次抓取

```
语音/界面 ──► 意图解析 ──► task_manager
                              │
                              ├─ action: NavigateToPose ──► Nav2 ──► 到达
                              │
                              ├─ 相机取图 ──► YOLO/RKNN ──► 目标框 + 深度
                              │
                              ├─ TF2: camera → arm_base（手眼标定结果）
                              │
                              ├─ 逆运动学 ──► 六关节角（含限位/奇异/碰撞检查）
                              │
                              ├─ SET_ARM_JOINTS ──► STM32 插补执行
                              │
                              ├─ 夹爪闭合 ──► 位置+电流双判据校验
                              │
                              └─ 失败 → 按类型重试或上报
```

状态机与失败分类见[软件结构](software-design.md#5-状态机)。

### 4.4 固件升级

```
APP 收到 OTA 指令（CMD 0x20~0x24）
   └─► 写 RTC 备份寄存器 magic ──► NVIC_SystemReset()
         └─► bootloader 读 magic
              ├─ 是 → DFU：接收数据 → 写 Flash → 校验整包 CRC → 跳转
              └─ 校验失败 → 保留旧镜像，上报
```

细节见[串口协议 · 升级命令段](protocol.md)。

## 5. 部署与运行

| 项目 | 做法 |
| --- | --- |
| 进程托管 | systemd，`Restart=always` + `WatchdogSec=10` |
| 启动顺序 | `After=` 控制依赖，避免节点起来找不到串口/地图 |
| 日志 | 分级写文件 + logrotate 轮转，防止写满 SD 卡 |
| 版本追溯 | `git describe` 编进二进制，启动时打印 |
| 配置 | 参数放 `config/`，地图放 `robot_bringup/maps/`，均入版本库 |

**为什么用 systemd 而不是自己 fork**：自动重启、启动依赖、日志统一、看门狗、资源限制，全部内置。自己写守护进程这些都要重造，且容易出错。

## 6. 构建体系

| 部分 | 工具 | 产物 |
| --- | --- | --- |
| ROS 2 包 | colcon + ament_cmake | `install/` 下的可执行文件 |
| STM32 固件 | CMake + arm-none-eabi | `.elf` / `.bin` / `.hex` |
| 交叉编译 | 工具链文件指定 sysroot | aarch64 二进制 |
| 模型 | Python 脚本 | `.onnx` → `.rknn` |

**交叉编译的关键**：sysroot 必须来自目标板本身（拷贝板上的 `/usr/lib`、`/usr/include`），否则编译通过、上板报 `GLIBC_2.xx not found`。

产物不入库（`.gitignore` 已覆盖），构建脚本放 `scripts/`。
