## 1. 为什么先量死区

速度环外环给定的是轮速，输出是占空比（‰）。直流减速电机在低占空比下不转：桥臂压降、电刷接触压降、齿轮静摩擦叠在一起，占空比必须超过某个阈值转子才起转。这个阈值就是**死区**。

死区不处理会带来两个具体问题：

1. **低速不可控**：目标 30 mm/s 时 PID 输出的占空比可能整段落在死区里，轮子要么不动、要么一旦积分攒够就突然蹦出去，表现为爬行/顿挫；
2. **零速漂移**：停车后积分残量作用在死区边缘，轮子可能缓慢爬行。现有代码用 `SERVICE_CHASSIS_ZERO_SPEED_EPS_MM_S` 在零目标时清积分，只能压住一部分。

量出死区后，才谈得上要不要加前馈补偿（把死区折成占空比偏置）以及积分项的下限。

**注意**：死区和负载强相关。架空（轮子离地）量到的是"空载死区"，落地后起转需要更大占空比。本文记录的是架空值，落地后要复测一次，两者都保留。

## 2. 测量前提

| 项目 | 要求 |
| --- | --- |
| 底盘 | **架空**，四轮悬空；或平地四周留 1 m，脚本会真的让轮子转 |
| 供电 | 电池电量充足并记录电压（`REPORT_STATUS` 的 `battery_mv`），低压时死区会变大 |
| 串口 | USB 转串口独占；**上位机 GUI 必须先关闭**，它持有 COM 口 |
| 固件 | 含 `SET_PARAM 0x30~0x33` 与 `REPORT_WHEEL_DUTY 0xC7` 的版本 |
| 轮序 | A = FL 左前，B = FR 右前，C = RL 左后，D = RR 右后 |

先确认链路和固件版本对得上：

```bash
python tools/bench/proto_loop.py --list
python tools/bench/proto_loop.py --port COM5 --monitor --duration 3
```

监听时应当能看到 `WHEEL_DUTY` 帧（0xC7），没有就说明烧的还是旧固件。

## 3. 死区测量

### 3.1 命令

```bash
python tools/bench/wheel_tune.py --port COM5 deadzone --yes
# 单轮复测（改完线序、换电机后用）：
python tools/bench/wheel_tune.py --port COM5 deadzone --wheels A --yes
```

工具按以下顺序工作：

1. `SET_ENABLE(1)` 使能底盘；
2. 对每个轮子、每个方向，用 `SET_PARAM 0x30~0x33` 以 40‰ 步长从 0 加到 400‰，每档保持 0.6 s，占空比每 100 ms 刷新一次（固件 300 ms 过期）；
3. 判定起转：该档末尾 40 % 时间窗内的平均速度 ≥ 10 mm/s；
4. 在起转的那一档内二分 4 次，得到 ±2.5‰ 的死区；
5. 全程用 `REPORT_WHEEL_DUTY` 回读实际写入的占空比，与下发值不一致时表格里能直接看出来；
6. 结束时 `SET_ENABLE(0)`。

单轮耗时约 12 s，四轮双向约 1.5 min。

### 3.2 可用参数

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `--step` | 40 | 粗扫步长（‰） |
| `--max-duty` | 400 | 扫描上限，固件硬上限也是 400 |
| `--hold` | 0.6 | 每档保持时间（s） |
| `--threshold` | 10 | 判定起转的速度阈值（mm/s） |

阈值取 10 mm/s 是因为编码器在 10 ms 采样下约 4 mm/s 一分度，低于这个数分不清"真在转"和量化抖动。

**判读要点**：

- 同一侧两个轮子的死区应接近；差得远说明机械装配（齿轮箱、轮毂）或电机个体有差异，先查机械再查电路；
- 正反向死区不对称是正常的（H 桥上下管压降、电机换向），但差超过 30‰ 要记录并观察是否随温度漂移；
- 死区处速度应是个位数到几十 mm/s；如果一过死区就跳到几百 mm/s，说明起转很"陡"，速度环低增益段需要特别小心。

## 4. 速度环整定

### 4.1 顺序

1. **先 Kp**：Ki = 0、Kd = 0，Kp 从 0.5 起按 ×1.5 递增，直到阶跃响应开始超调或振荡，取振荡前一级的 70 %；
2. **再 Ki**：在上一步 Kp 下加 Ki，目标是稳态误差 < 5 %，Ki 加到误差达标且不明显增加超调为止；
3. **Kd 保持 0**：10 ms 采样速度做微分主要是放大量化噪声，除非后续给速度加滤波，否则不开。

### 4.2 命令

```bash
# 单组增益，四轮一起测
python tools/bench/wheel_tune.py --port COM5 step --speed 200 --yes

# 增益扫描：Kp 两档、Ki 一档（会跑 2 组）
python tools/bench/wheel_tune.py --port COM5 step --speed 200 \
    --kp 1.0 1.5 --ki 0.6 --yes

# 只测一个轮子
python tools/bench/wheel_tune.py --port COM5 step --wheels A --speed 200 --yes
```

工具以 50 Hz 下发 `SET_VELOCITY(vx=200, wz=0)`，记录 2 s 的 `REPORT_WHEEL_SPEED`，逐轮算：

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 稳态 | 最后 0.8 s 的平均轮速 | — |
| 误差 | (稳态 − 目标) / 目标 | **< 5 %** |
| 上升时间 | 达到稳态值 10 %→90 % 的时间 | < 0.3 s |
| 超调 | (峰值 / 稳态 − 1) | < 15 % |
| 纹波 | 最后 0.8 s 内峰峰值 | < 40 mm/s |

直行时四个轮子目标相同（逆解 `vx=200, vy=wz=0` 时四轮都是 200 mm/s），所以同一组增益下四轮指标可以直接横向比较。

**判读要点**：

- 四轮用同一组增益还是分别整定：先试统一增益，若某一轮的误差或超调明显偏离其他三轮，再单独整定该轮（`SET_PARAM` 本来就支持逐轮写）；
- 纹波受编码器量化影响，200 mm/s 下 ±40 mm/s 属于正常范围，不要把纹波当成振荡去降增益；
- 低速（30~50 mm/s）单独测一遍：死区补偿缺失时这里最容易出现"走走停停"。

## 5. 低速与死区补偿（视测量结果决定）

如果 3.3 的死区在 200 mm/s 以下的常用速度带里占的比重超过约 20 %，考虑加前馈：

```text
duty_cmd = pid_out + sign(target) * deadzone_permille
```

实现位置在 `service_chassis_apply()` 的闭环分支，`service_chassis_pid_duty()` 限幅之前。**先不实现**：等 3.3、4.3 的数据出来，确认低速确实抖再动，避免凭猜测加补偿量。

## 6. 回填与固化

### 6.1 回填编译期默认值

整定完成后，把选定增益写进 `firmware/app/01_APP/app_robot/app_robot_config.h`：

```c
#define APP_CHASSIS_LEFT_PID_KP   ((float_t)?.?f)   /* 实测值 */
#define APP_CHASSIS_LEFT_PID_KI   ((float_t)?.?f)
#define APP_CHASSIS_LEFT_PID_KD   ((float_t)0.0f)
#define APP_CHASSIS_RIGHT_PID_KP  ((float_t)?.?f)
#define APP_CHASSIS_RIGHT_PID_KI  ((float_t)?.?f)
#define APP_CHASSIS_RIGHT_PID_KD  ((float_t)0.0f)
```

如果四轮分别整定，`service_chassis_cfg_t` 已经提供了按轮数组（`pid_kp[4]` 等），需要在 `app_user_init.c` 里逐轮赋值，而不是只给左右两组。

### 6.2 写外部 Flash（待实现）

目前 `SET_PARAM` 写增益只改 RAM，掉电恢复编译期初值（`docs/architecture/protocol.md` §5.4）。外部 Flash 参数存储完成后：

1. `SET_PARAM` 写增益成功后在 RAM 生效，并置"参数脏"标志；
2. 由控制任务（非通信任务）在总线空闲时写入参数区，避免两个任务同时擦写；
3. 上电时从 Flash 读参数，校验 CRC 失败或空白则退回 `app_robot_config.h` 的编译期值；
4. 写成功后 `REPORT_STATUS` 增加一个"参数已固化"标志位，主机才知道可以断电。

**在那之前，本文件的数值是唯一的记录**，重烧固件就会丢失运行期整定结果。

## 7. 已知限制

| 限制 | 影响 | 处理 |
| --- | --- | --- |
| 死区是架空测量值 | 落地后起转占空比偏大 | 落地后按 3.1 复测一次，两套值都记录 |
| 电池电压会改变死区 | 满电/亏电表现不同 | 每次测量记录 `battery_mv`，跨电压对比前先看电压 |
| 速度反馈是 10 ms 差分 | 单分度约 4 mm/s，纹波下限 | 不要用低于 40 mm/s 的目标评估 PID 好坏 |
| 增益不持久化 | 断电/复位丢失 | 见 6.2，固化实现前重新下发 |
| 测试占空比上限 400‰ | 无法测满转特性 | 需要满转数据时用闭环 `step` 命令 |
| GUI 与台架脚本争用串口 | 打不开 COM 口 | 测前关闭上位机 |
